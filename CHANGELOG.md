### Notes

- Typed response DTOs ship for the highest-hit endpoints in `MarketService`,
  `TradeService`, `AccountService`, and `PositionService` this release
  (`Ticker`, `TickersResult`, `KlineResult`, `OrderbookResult`, `ServerTimeResult`,
  `CreateOrderResult`, `AmendOrderResult`, `CancelOrderResult`, `OpenOrdersResult`,
  `OrderHistoryResult`, `TradeHistoryResult`, `BatchCreateOrdersResult`,
  `BatchAmendOrdersResult`, `BatchCancelOrdersResult`, `CancelAllOrdersResult`,
  `PreCheckOrderResult`, `SpotBorrowQuotaResult`, `WalletBalanceResult`,
  `PositionInfoResult`). Other endpoints still return `ApiResponse<unknown>`
  and will get typed responses in follow-up releases.
- `EarnService.*` and `PWM*` bodies use hand-written `interface` types for their
  nested `Record<string, unknown>` fields, so key names are checked at compile
  time even where individual values are still `unknown`.
- `BotService` methods (`createGridBot`, `createFuturesGridBot`, `createComboBot`,
  `createFuturesMartingaleBot`, `createDcaBot`, and their `close*` / `get*` /
  `validate*` peers) accept `camelCase` params on the call site and translate
  to `snake_case` on the wire. `createDcaBot.parameters` is a passthrough object
  and must use the keys from the Bybit docs verbatim.
